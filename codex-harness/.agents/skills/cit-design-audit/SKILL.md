# CiT Design Audit

검수(preflight), 제작 후 검증, Claude·Codex 결과 비교에 이 스킬을 쓴다.

## 작업 순서

1. `config/harness-policy.json`과 거기서 가리키는 살아있는 SSOT를 읽는다.
2. 정확한 파일, 페이지, 노드를 확인한다. 대상을 조회하고 스크린샷을 확보한다.
3. 확정된 SSOT 규칙, 후보 인벤토리 패턴, 검수자 판단을 구분한다.
4. 시각적 위계, 타이포그래피, 여백·정렬, 대비 위험, 언어 품질, 에셋 무결성, 캠페인 세트 간 일치, 범위 이탈을 확인한다.
5. 정확한 근거와 함께 심각도별로 결과를 보고하고, 원본을 바꾸지 않는 교정안을 제시한다.
6. Figma 쓰기·생성·동기화·삭제·publish 동작을 호출하지 않는다. 발견한 문제를 자동으로 고치지 않는다.

## 판정 형식 — 셀 수 있게 보고한다

판정은 느낌이 아니라 건수로 낸다. 아래 형식을 따른다.

```
■ 검수 결과 — {대상}

GO        {N}건
보류      {N}건

보류 사유
  {파일/페이지/노드}  {항목}  현재 {값} → 기준 {값}
  …
```

**수치는 도구 출력(스크린샷, `get_metadata`, `get_design_context` 결과)에서 그대로 인용한다.** 기억이나 짐작으로 적지 않는다. 보류가 하나라도 있으면 완료로 보고하지 않는다.

판단이 애매한 항목은 GO로 몰지 않고 사용자에게 묻는다.

최종 독립 검수가 필요하면 리뷰만 `cit_design_auditor`에 위임하고 결과를 기다린다.

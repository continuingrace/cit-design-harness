# 익스포트 전 검수 — 게이트 B

대상: **$ARGUMENTS**

---

## 0. 이 검수의 절대 규칙 — 먼저 읽는다

> **이 스킬은 본 세션에서 돈다. 포크가 아니다.**
>
> 원래 `context: fork` 로 만들었다가 걷어냈다. 이유 두 가지 —
> ① 포크에서 Figma 를 못 읽었다. (나중에 원인은 MCP 미인증으로 밝혀졌지만, ② 가 남아 있어 되돌리지 않았다)
> ② `background: false` 가 Claude Code **v2.1.218 이상**에서만 동작하는데
>    이 환경은 2.1.118 이라 무시된다 → 검수가 백그라운드로 돌아 게이트 노릇을 못 한다.
>
> 대신 **격리를 잃었다.** 방금 자기가 만든 것을 자기가 검수하게 된다.
> 그래서 아래 두 줄을 지킨다.
>
> - **만든 턴에서 바로 GO 를 선언하지 않는다.** 검수는 별도 요청으로 돌린다.
> - **수치는 도구 출력에서 그대로 인용한다.** 기억이나 짐작으로 적지 않는다.
>
> 나중에 CLI 를 2.1.218 이상으로 올리고 포크에 Figma MCP 가 실리는 것을 확인하면
> `context: fork` · `agent: Explore` · `background: false` 를 다시 넣는다.

```
0. 이 세션이 쓰기 세션이면 검수하지 않는다
     FIGMA_WRITE 가 켜져 있으면 (세션 시작 줄에 "⚠ Figma 쓰기 세션" 경고가 떴으면)
     검수를 거부하고 사용자에게 알린다:
       "지금은 쓰기 세션입니다. 검수는 FIGMA_WRITE 를 끈 새 세션에서 돌려주세요.
        자기가 만든 것을 자기가 채점하게 됩니다."
1. Figma 원본을 고치지 않는다. 조회만 한다 (get_design_context · get_screenshot · get_metadata)
2. 고쳐야 할 것이 보이면 고치지 말고 목록으로 낸다
3. 기존 원본 수정은 사용자 승인 후에만 — 이 스킬에서는 승인을 받지 않는다
4. 수정 승인이 필요하면 파일 키 · 페이지 · 프레임명 · 노드 ID 를 전부 적어 사용자에게 올린다
5. 새로 만드는 것은 스테이징 영역(AI_CLAUDE__<작업명>)에서만 — 이 스킬에서는 만들지 않는다
6. 검수를 통과하기 전에는 익스포트도, 원본 반영도 하지 않는다
7. 판정만 한다. 판단이 애매하면 GO 하지 말고 사용자에게 묻는다
```

**진짜 차단은 프론트매터가 아니라 훅이 한다.**
`disallowed-tools` 는 도구 이름을 정확히 알아야 하고 구버전에서 무시될 수 있다.
`block-figma-write.mjs` (PreToolUse 훅) 가 이름 공간과 무관하게 Figma 쓰기를 막는다 —
확인된 조회 도구만 통과시키고, 모르는 도구는 차단한다(fail-closed).
`disallowed-tools` 는 보조 레이어로 남겨둔다.

## 1. 수치 검사

`${CLAUDE_PLUGIN_ROOT}/spec.json` 의 확정 규칙에 대고 검사한다.

| 항목 | 기준 |
|---|---|
| 서체 | ExampleSans (보조 서체는 경고) |
| 자간 | 국문 −1.5% · 영문 대문자 라벨은 **판정 안 함**(미확립) · 600×400 예시 메시지 가변 허용 |
| 좌마진 | 일반 게시물 72px · 표지 112px · 광고 96px |
| 광고 하단 | 240px 안에 텍스트 금지 |
| 프레임명 | `{YYMMDD}_{종류}_{본부}_{번호}_{버전}` · 같은 페이지 내 중복 금지 |

**주의** — 마진·하단 규칙은 `spec.json` 의 `effectiveFrom` 이후 작업에만 적용된다.
그 전 작업이 걸리면 위반이 아니라 참고다.

전체를 다시 훑으려면 (조회 전용 · GET만 호출):

```
node ${CLAUDE_PLUGIN_ROOT}/figma-inventory.mjs
```

특정 프레임만 볼 때는 Figma MCP 로 직접 읽는다.
**Figma MCP 를 쓸 수 없으면 그 자리에서 멈추고 알린다.** 추측으로 판정하지 않는다.
인증이 안 된 상태일 수 있으니 `/mcp` 로 `figma` 인증 상태를 확인하라고 안내한다.

## 2. 눈 검사

일러스트가 들어간 세트면 `anthropic-skills:illustration-consistency-check` 를 호출한다.
컷 간 인물·소품·배경이 바뀌는 문제, 손·손가락·원근 오류, 물리적으로 불가능한 결합을 잡는다.

그 스킬이 이 세션에 없으면 **눈 검사를 건너뛰었다고 명시**한다. 조용히 통과시키지 않는다.

## 3. 세트 일치 — 이 게이트의 고유 항목

낱장이 다 맞아도 **세트가 따로 놀면 실패**다. 한 세트의 채널들을 나란히 놓고 본다.

- 배색이 전 채널에서 같은가 (인스타만 다른 색이면 실패)
- 같은 문구가 채널마다 다르게 쓰였는가
- 표지의 톤과 본문의 톤이 이어지는가
- 광고 파생본에서 푸터가 하단 240px 안으로 내려가 있지 않은가

> 실제로 걸린 적 있는 항목이다. 카드뉴스 푸터가 y=1266 인데,
> 그대로 광고로 돌리면 참여 버튼에 가린다.

## 규칙이 계속 걸릴 때

같은 규칙에서 보류가 반복되면 **규칙을 의심한다.**
600×400 예시 메시지 자간이 그런 사례였다 — 이탈로 보였는데 의도된 운영 방식이었다.

그럴 땐 고치라고 하지 말고 이렇게 보고한다.

> "{규칙}에서 {N}건이 반복해서 걸립니다. 규칙이 현실과 안 맞는 것 같은데,
>  규칙을 바꿀까요, 작업을 맞출까요?"

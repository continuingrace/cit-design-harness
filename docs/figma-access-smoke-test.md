# Figma 접근 권한 로컬 점검

이 점검은 회사 Figma 계정으로 수행한다. 토큰이나 인증정보를 Codex 대화, PR, 저장소 파일에 붙이지 않는다. 실제 원본 대신 승인된 빈 복제 파일을 준비한다.

## 1. 권한 경계 설정

- Codex가 사용하는 Figma 계정은 원본 파일을 **Can view**로만 연다.
- 제작할 별도 `AI_CODEX__<task>` 스테이징 파일에만 해당 계정의 편집 권한을 준다.
- 사람의 주 계정과 Codex 계정이 같으면 Figma가 사람과 에이전트를 구분하지 못한다. 이 경우 원본 쓰기 권한을 기술적으로 분리할 수 없으므로, Codex에게 원본을 열지 말고 독립된 스테이징 파일만 제공한다.
- 원본 안의 새 페이지는 권한 격리가 아니다. 파일 전체가 편집 가능하면 Codex도 그 파일 전체를 수정할 수 있다.

## 2. 읽기 전용 인벤토리 확인

VS Code PowerShell에서 저장소 루트부터 실행한다. 토큰은 File content `Read`만 허용한다.

```powershell
Set-Location .\claude-inventory
$secureToken = Read-Host "Figma 읽기 전용 토큰" -AsSecureString
$env:FIGMA_TOKEN = [System.Net.NetworkCredential]::new("", $secureToken).Password
node .\figma-inventory.mjs --file "<files.json의 테스트 파일 별칭>"
Remove-Item Env:FIGMA_TOKEN
```

실패하면 `out/` 결과를 성공한 검사로 취급하지 않는다. 토큰 값을 출력하거나 다른 사람에게 보내지 않는다.

## 3. 복제 파일에서 플러그인 권한 확인

공식 Figma 플러그인을 Codex에 연결하고 아래를 실제로 시도한다.

| 대상 | 시도 | 기대 결과 |
|---|---|---|
| 테스트용 원본 복제(계정은 보기 전용) | 읽기/스크린샷 | 허용 |
| 같은 파일 | 이름이 표시되지 않는 새 노드 생성 | Figma 권한에서 거부 |
| 별도 AI staging 파일 | 테스트 사각형 1개 생성 | 허용 |
| staging 파일 | 테스트 사각형 업데이트 후 스크린샷 확인 | 결과가 요청한 노드/범위와 일치 |

원본 복제에서 쓰기가 성공하면 중단한다. 권한 계정과 파일 공유 설정을 다시 확인하고, 원본은 계속 보기 전용으로 유지한다. 테스트 staging 파일의 테스트 노드는 결과를 기록한 뒤 제거한다.

## 4. 남길 증거

작업 PR의 계획에 날짜, Figma 테스트 파일 별칭, 권한별 허용/거부 결과, 스크린샷 위치, 테스트 정리 여부를 기록한다. 원본 파일의 민감한 내용이나 토큰은 기록하지 않는다.

이 실행공간은 Figma에 연결되지 않아 이 점검의 실제 허용/거부 결과는 아직 확인되지 않았다. 아래를 모두 충족한 뒤에만 보고서에서 해당 검증 제한을 해소한다.

- 원본 파일 쓰기가 Figma 권한에서 실제 거부됨
- 별도 staging 파일 쓰기와 사후 읽기 검수가 성공함
- Ed25519 승인 키 검증기가 유효한 서명은 통과시키고 범위·해시·서명 변경은 거부함
